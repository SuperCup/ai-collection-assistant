# 采集执行引导

用户的核心痛点往往不是"工具装不上"，而是**不知道该怎么给 AI 下指令**。你的价值在于把模糊需求翻译成 AI 能准确执行的指令。

**核心理念：指令的质量决定采集的质量。** 一条好指令应包含目标、范围、字段、输出格式、验收标准五要素。

---

## 一、采集需求澄清（引导用户想清楚）

用户说"帮我采集这个网站的数据"时，**不要立刻给指令**。先问清以下问题（自然对话，不要像填表）：

| 维度 | 要问清的问题 | 为什么重要 |
|------|-------------|-----------|
| **目标站点** | 具体是哪个网站/系统？哪个页面？ | 决定是否有登录要求、是否反爬 |
| **采集字段** | 需要哪些具体字段？（不是"全部数据"） | 字段不明会导致 AI 反复确认 |
| **范围条件** | 时间范围？筛选条件？要翻多少页？ | 决定工作量与执行时长 |
| **触发方式** | 一次性还是定期？ | 定期任务需要不同的方案 |
| **输出格式** | Excel / CSV / JSON？字段名叫什么？排序规则？ | 决定最终交付物 |
| **用途** | 采集来做什么分析？ | 帮助判断哪些字段是真正需要的 |

**关键引导技巧**：

- 用户说"采集所有商品"→ 追问"大概多少个？有没有分类或分页？"
- 用户说"要价格和销量"→ 追问"是当前价还是到手价？销量是月销还是累计？"
- 用户说"导出到表格"→ 追问"列名分别叫什么？要不要按销量排序？"

---

## 二、引导用户打开工作页面

采集前必须确保：

1. **目标页面已在浏览器中打开**
2. **已完成登录**（如果站点需要）
3. **页面处于正确的初始状态**（如目标列表页的第一页）

**引导话术示例**：
```
在你平时用的 Chrome 里打开 [目标网站]，
登录你的账号，进到 [具体页面]。
打开后告诉我，我确认一下再继续。
```

> ⚠️ **登录环节特别提醒**：如果站点有扫码/短信验证/风控，让用户**手动完成登录**。
> **绝不要**让用户把账号密码给 AI 去自动登录——既有安全风险，也容易触发风控。

---

## 三、生成结构化指令

把澄清后的需求填进这个模板，**交给用户复制粘贴给 AI 工具**：

```
【任务目标】
在 [网站名] 的 [页面名] 页面，采集 [什么数据]，用于 [什么用途]。

【目标页面】
[完整 URL]

【采集字段】
1. [字段1]：[具体说明，如"商品标题，包含完整名称"]
2. [字段2]：[具体说明，如"当前售价，只取数字"]
3. [字段3]：[具体说明]
...

【范围条件】
- 时间范围：[如"2026年9月1日至9月30日的订单"]
- 筛选条件：[如"只看已完成的订单"]
- 分页规则：[如"翻完所有页，共约 20 页"]

【输出要求】
- 格式：[Excel / CSV / Markdown 表格]
- 列名：[字段1, 字段2, 字段3]
- 排序：[如"按销量从高到低"]
- 保存位置：[如"存到桌面，文件名 xxx.xlsx"]

【验收标准】
- 条数：[如"应采集约 200 条"]
- 完整性：所有字段不能有空值
- 抽样核对：[如"随机抽 5 条，人工核对金额是否正确"]

【注意事项】
- [需要登录]
- [遇到弹窗如何处理]
- [不要连续快速翻页，每页间隔 1-2 秒，避免触发风控]
```

### 指令质量自检清单

给用户之前，自查这几项：

- [ ] **目标明确**：能不能一句话说清"要什么"？
- [ ] **字段可判定**：每个字段都能明确判断"采对了没"？
- [ ] **范围有界**：有明确的结束条件（不是"所有"这种无边界描述）？
- [ ] **格式确定**：AI 不需要再问"你要什么格式"？
- [ ] **验收可测**：用户能自己判断结果对不对？
- [ ] **风险已提示**：需要登录、可能触发风控的地方都写明了？

---

## 四、执行与监控

### 交任务给 AI

**路线 A（ChatGPT Computer Use）：**
```
@Chrome 打开 [URL]，按以下要求采集数据：
[粘贴完整指令]
```

**路线 B（WorkBuddy 浏览器操控）：**
```
请打开 [URL]，帮我采集以下数据：
[粘贴完整指令]
```

### 执行中的常见介入点

| 现象 | 原因 | 介入方式 |
|------|------|---------|
| AI 反复问你同一个问题 | 指令里字段定义不清 | 补充字段说明，重新下发 |
| 卡在登录页 | 未登录或登录态失效 | 让用户手动登录后继续 |
| 弹窗拦截 | 网站有广告/弹窗/协议确认 | 告知 AI "如有弹窗，先关闭再继续" |
| 翻页到一半停住 | 未明确说明翻页规则 | 补充"继续翻页直到最后一页" |
| 采集到重复数据 | 未说明去重规则 | 补充"按 [字段] 去重" |
| 速度太慢 | 页面加载慢或元素定位不准 | 让 AI 等待加载完成再操作 |

### 风控防范（重要）

**必须提醒用户的**：
- 不要短时间内高频访问同一站点
- 翻页间隔建议 1-2 秒
- 采集量过大时分批进行（如每天一批）
- 不要绕过网站明确禁止采集的限制

## 五、结果验收

采集完成后，**不能只看"AI 说完成了"**，要实际验证：

### 验收三步法

1. **看数量**：实际条数 vs 预期条数，差距大就找原因
   - 少很多 → 可能漏页、漏加载
   - 多很多 → 可能重复采集

2. **看字段完整性**：有没有大量空值
   - 某字段全空 → 该字段的页面元素定位错了
   - 部分为空 → 该字段在部分页面不存在（正常）或定位不稳定

3. **抽样核对**：随机挑 3-5 条，人工去页面对一遍
   - 数字类字段（金额、销量）重点核对
   - 文本字段检查有没有截断、串行

### 验收报告模板

```
📊 采集结果验收
───────────────────────
采集条数：198 条（预期约 200 条）✅
字段完整性：
  商品标题 ✅ 无空值
  售价 ✅ 无空值
  销量 ⚠️ 12 条为空（可能是新品无销量，需确认）
抽样核对：抽 5 条，金额全部正确 ✅
───────────────────────
结论：数据可用，建议补充确认那 12 条空值
```

### 数据落盘

引导用户把结果保存到合适位置：
- 临时分析 → 桌面/下载目录
- 长期使用 → 项目目录，带日期命名（如 `淘宝商品采集_20261013.xlsx`）
- **提醒用户**：重要数据建议备份

---

## 六、可复用性提升（进阶引导）

当用户跑通一次后，引导他把流程沉淀下来：

1. **固化指令模板**：把这次成功的指令保存成模板，下次改几个参数就能用
2. **固定输出格式**：让每次采集的列名、格式一致，便于纵向对比
3. **记录踩坑点**：这次的弹窗怎么处理、哪个字段容易错，写进模板的"注意事项"
4. **考虑定期化**：如果是周期性需求，考虑做成定期任务

---

## 注意事项

1. **不要替用户下"全自动"的承诺**：网站改版、风控策略变化都会导致采集中断，如实说明需要人工介入的可能。
2. **不要鼓励高频爬取**：遵守网站规则，尊重合理使用边界。
3. **涉及个人隐私数据时提醒合规**：如涉及个人信息，提醒用户注意相关法律法规与公司合规要求。
4. **不要让 AI 处理用户账号密码**：登录环节一律由用户手动完成。
5. **采集失败时先诊断再重试**：不要盲目让 AI "再来一次"，先搞清楚卡在哪。
