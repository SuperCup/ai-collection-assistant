# 常见问题与解决方案（FAQ 知识库）

排查原则：**先定位环节，再看具体现象，一次只给一个动作。**

---

## 通用排查心法

### 三步定位法

```
第 1 步：这个环节是"装"还是"配"还是"用"？
  ├─ 装不上 → 看网络、看权限、看源
  ├─ 配了不生效 → 看是否激活、看是否重启、看配置文件写对没
  └─ 用起来报错 → 看认证、看网络、看模型名

第 2 步：错误信息在哪一层？
  网络层（超时/连接被拒）→ 网络问题
  认证层（401/403）→ 密钥问题
  应用层（模型不存在/参数错）→ 配置项问题

第 3 步：给用户一个可验证的动作
  不要说"可能有两个原因，你试试"，而是"先执行这个命令，把输出发我"
```

### 排查话术模板

```
先确认一下现象：你看到的具体报错是什么？（截图或文字都行）
```

> **不要一上来就给方案**。先拿到现象，再定位，再给一个动作。

## 一、环境检测类

### Q1：命令执行超时 / 长时间无响应

| 项 | 内容 |
|---|---|
| **现象** | 检测网络时卡住不动，或 curl 长时间无返回 |
| **原因** | 目标站点不通，命令在等待超时 |
| **解决** | 确认检测命令带了 `--max-time 5`；网络不通时超时是**预期结果**，不是故障 |

### Q2：Chrome 明明装了，却检测不到

| 项 | 内容 |
|---|---|
| **现象** | 脚本报"Chrome not found"，但用户说电脑上装了 |
| **原因** | Chrome 安装路径不在 `%LOCALAPPDATA%`，而在 `C:\Program Files\Google\Chrome\Application\` |
| **解决** | 多路径探测，顺序：`Program Files → Program Files (x86) → LOCALAPPDATA → Chrome SxS → Edge` |

### Q3：用户说"我能翻墙"，但实测不通

| 项 | 内容 |
|---|---|
| **现象** | 用户确信自己能访问境外站点，但检测失败 |
| **原因** | ①代理软件没开 ②代理只在浏览器生效（系统级未走代理）③代理规则未覆盖目标域名 |
| **解决** | 让用户打开代理软件并开启系统代理/全局模式后再测；确认终端也走了代理 |

## 二、ChatGPT 桌面版类

### Q4：安装包下载慢或下载失败

| 项 | 内容 |
|---|---|
| **现象** | 从官网下载 ChatGPT 安装包极慢或中断 |
| **原因** | 国内网络访问境外下载源受限 |
| **解决** | ①优先用 Microsoft Store（Windows，微软 CDN 国内可达）②从公司/组织内部正规途径获取安装包 ③先解决网络访问问题 |

> ⚠️ **绝不推荐**：第三方"加速下载站"、汉化版、绿色版、整合包。

### Q5：ChatGPT 装好了但登录不上

| 项 | 内容 |
|---|---|
| **现象** | 打开桌面版后卡在登录页，或登录报错 |
| **原因** | ①网络无法访问 OpenAI 认证服务 ②账号地区限制 ③账号未订阅对应套餐 |
| **解决** | 确认网络能访问 chatgpt.com 与 auth.openai.com；确认账号套餐包含所需功能 |

### Q6：找不到 Computer Use 入口

| 项 | 内容 |
|---|---|
| **现象** | 用户进了 ChatGPT 却找不到 Computer Use |
| **原因** | ①不在 Work / Codex 视图下 ②账号套餐不支持 ③功能灰度未覆盖 ④未安装插件 |
| **解决** | ①切换到 Work 或 Codex 视图 ②确认是付费账号 ③进入 `Plugins → Computer Use` 点 Install plugin ④开启 server 与 skill 两个开关 |

### Q7：Computer Use 运行时鼠标被"抢走"了（Windows）

| 项 | 内容 |
|---|---|
| **现象** | 任务执行时鼠标键盘不受控，无法做其他事 |
| **原因** | **Windows 下 Computer Use 是前台接管模式**，这是设计行为，不是故障 |
| **解决** | ①提前告知用户这是正常的 ②任务运行时不要操作电脑 ③需要同时办公时，考虑在虚拟机中运行，或用 WorkBuddy 路线 |

### Q8：macOS 上 Computer Use 看不到画面 / 点不动

| 项 | 内容 |
|---|---|
| **现象** | macOS 下 AI 看不到目标应用，或看到但无法点击 |
| **原因** | 缺少系统权限 |
| **解决** | 授予**屏幕录制**（看）+ **辅助功能**（点），两项缺一不可。在"系统设置 → 隐私与安全性"里开启后需**重启 ChatGPT 应用** |

## 三、cc-switch 类

### Q9：保存了供应商配置，但 CLI 仍报 Invalid API key

| 项 | 内容 |
|---|---|
| **现象** | cc-switch 里配好了中转站，运行 CLI 仍认证失败 |
| **原因** | **配置保存 ≠ 生效**。cc-switch 需要"主动激活"供应商 |
| **解决** | 回到 cc-switch，**点击该供应商卡片激活**（卡片前出现勾选标记/高亮态），再重试 |

### Q10：切换供应商后仍走旧的配置

| 项 | 内容 |
|---|---|
| **现象** | cc-switch 已切换，但 CLI 行为没变 |
| **原因** | 已打开的终端会话仍持有旧的环境变量 / 配置文件在启动时读取 |
| **解决** | **关闭当前终端，重新开一个新终端**再运行 CLI。CLI 类工具普遍需要重启终端 |

### Q11：cc-switch 装不上 / 打不开（macOS）

| 项 | 内容 |
|---|---|
| **现象** | macOS 提示"无法验证开发者" |
| **原因** | 旧版本未做代码签名 |
| **解决** | 最新版本已签名公证可直接打开；若仍提示，去"系统设置 → 隐私与安全性"点击"仍要打开"；或改用 `brew install --cask cc-switch` |

### Q12：cc-switch 能不能给 ChatGPT 换后端？

| 项 | 内容 |
|---|---|
| **现象** | 用户想让 ChatGPT 桌面版走中转站 |
| **原因** | **技术上做不到** |
| **解决** | 如实说明：cc-switch 管理的是 Claude Code / Codex CLI / Gemini CLI 等**命令行工具**的配置。ChatGPT 桌面版只能走 OpenAI 官方账号。如需中转站能力，改用支持自定义后端的 CLI 工具 |

## 四、中转站配置类

### Q13：curl 测试返回 401 / 403

| 项 | 内容 |
|---|---|
| **现象** | 连通性测试报认证失败 |
| **原因** | ①Key 复制时带了多余空格或换行 ②Key 已失效/额度用尽 ③Header 格式不对 |
| **解决** | 检查 Key 首尾无空格；确认 Header 是 `Authorization: Bearer <key>`；向管理员确认 Key 状态 |

### Q14：curl 测试返回 404

| 项 | 内容 |
|---|---|
| **现象** | 地址访问不到 |
| **原因** | **Base URL 漏了 `/v1` 后缀**（最常见） |
| **解决** | 确认地址以 `/v1` 结尾，如 `https://xxx.example.com/v1`，测试用 `{BaseURL}/models` |

### Q15：curl 测试超时

| 项 | 内容 |
|---|---|
| **现象** | 连接超时，无返回 |
| **原因** | ①网络不通 ②地址拼写错误 ③中转站是内网地址，需在公司网络内访问 ④中转站服务故障 |
| **解决** | 先 ping 域名确认可达；确认是否需要内网/VPN；向内网管理员确认服务状态 |

### Q16：测试通了，但 CLI 报"模型不存在"

| 项 | 内容 |
|---|---|
| **现象** | 认证通过，但调用报模型错误 |
| **原因** | 模型名写错。中转站的模型名**必须精确匹配** |
| **解决** | 用 `curl {BaseURL}/models` 拉取实际可用模型列表，用返回值里的**精确 id** 填入配置 |

### Q17：API Key 应该放哪？会不会泄露？

| 项 | 内容 |
|---|---|
| **说明** | API Key 只写入**用户本机的配置文件**（`~/.claude/settings.json`、`~/.codex/config.toml`、cc-switch 的本地数据库等） |
| **红线** | **绝不**写入专家包目录、脚本、README、聊天记录截图、共享文档 |
| **建议** | 如需分享配置方法给同事，只分享"填哪里"，不分享"填什么" |

## 五、CLI 工具类

### Q18：npm 安装超时 / 卡住

| 项 | 内容 |
|---|---|
| **现象** | `npm install -g` 长时间无进展 |
| **原因** | 默认源在国外，国内网络访问慢 |
| **解决** | `npm config set registry https://registry.npmmirror.com` 后重试 |

### Q19：Windows 报"禁止运行脚本"

| 项 | 内容 |
|---|---|
| **现象** | PowerShell 报 `无法加载文件 ...ps1，因为在此系统上禁止运行脚本` |
| **原因** | PowerShell 执行策略限制 |
| **解决** | 管理员 PowerShell 执行 `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser`，选 Y 确认 |

### Q20：命令找不到（command not found）

| 项 | 内容 |
|---|---|
| **现象** | 装完了但敲命令提示找不到 |
| **原因** | ①安装未真正完成 ②PATH 未刷新（需重开终端）③Node.js 未装或版本过低 |
| **解决** | 关掉终端重新开一个；`node -v` 确认 Node 版本 ≥ 18（推荐 22+）；重新执行安装命令看有无报错 |

## 六、浏览器扩展类

### Q21：扩展装了但没生效

| 项 | 内容 |
|---|---|
| **现象** | 扩展图标在，但 AI 工具说连接不上浏览器 |
| **原因** | ①扩展被禁用 ②浏览器未运行 ③扩展权限未授予 ④桌面端需要重启 |
| **解决** | ①`chrome://extensions` 确认扩展为启用状态 ②确保浏览器正在运行 ③重启 AI 桌面应用（ChatGPT / WorkBuddy）后重试 |

### Q22：怎么确认扩展是官方版本？

| 项 | 内容 |
|---|---|
| **现象** | 商店里搜到多个同名扩展，不知道装哪个 |
| **原因** | 第三方会用相似名称混淆 |
| **解决** | ①确认**发布者名称**（ChatGPT 扩展发布者应为 **OpenAI**）②优先从 AI 桌面应用内的官方入口安装（如 ChatGPT 的 `Plugins → Chrome`）③核对商店链接是否为官方页面 |

### Q23：WorkBuddy 报 extension_disconnected

| 项 | 内容 |
|---|---|
| **现象** | WorkBuddy 提示扩展未连接 |
| **原因** | 扩展被禁用、浏览器关闭、或连接中断 |
| **解决** | 检查扩展启用状态 → 确认浏览器在运行 → 在 WorkBuddy 中重新获取浏览器列表（不要复用旧的浏览器标识） |

### Q24：多个浏览器装混了

| 项 | 内容 |
|---|---|
| **现象** | 扩展装在了 Edge，但操作的是 Chrome |
| **原因** | 扩展按浏览器独立安装，切换浏览器需重新安装 |
| **解决** | 明确固定使用一个浏览器。更换浏览器时，**必须在新的浏览器里重新安装扩展**，并使用安装了扩展的那个浏览器配置文件 |

## 七、采集执行类

### Q25：AI 反复问同一个问题

| 项 | 内容 |
|---|---|
| **现象** | AI 执行时反复确认字段含义，无法推进 |
| **原因** | 指令里的字段定义模糊 |
| **解决** | 补充字段的**精确定义**（如"售价 → 页面价格区域的数字，不含货币符号"），重新下发指令 |

### Q26：卡在登录页

| 项 | 内容 |
|---|---|
| **现象** | AI 无法继续，页面停在登录界面 |
| **原因** | 未登录或登录态失效 |
| **解决** | **由用户手动完成登录**（扫码/短信/密码）。绝不让 AI 处理账号密码 |

### Q27：弹窗导致采集中断

| 项 | 内容 |
|---|---|
| **现象** | 弹出广告、协议确认、优惠券弹窗，AI 卡住 |
| **原因** | 指令未说明弹窗处理方式 |
| **解决** | 在指令的"注意事项"里补充："如遇到任何弹窗，先关闭再继续采集" |

### Q28：翻页到一半停住

| 项 | 内容 |
|---|---|
| **现象** | 采集了几页就停了 |
| **原因** | 未明确说明翻页规则，或页面加载慢导致元素未就绪 |
| **解决** | 补充"继续翻页直到最后一页"；对加载慢的页面，补充"等列表加载完成后再采集" |

### Q29：采集结果有重复

| 项 | 内容 |
|---|---|
| **现象** | 同一条数据出现多次 |
| **原因** | 未说明去重规则，或翻页时页面未完全刷新 |
| **解决** | 补充"按 [唯一标识字段] 去重"；检查是否需要等页面刷新完成再采下一页 |

### Q30：字段大量为空

| 项 | 内容 |
|---|---|
| **现象** | 某个字段几乎全是空值 |
| **原因** | 字段定位规则不对（AI 没找到对应页面元素） |
| **解决** | 让用户截图标注该字段在页面的**具体位置**，补充到指令里；或调整为"从 XX 位置提取" |

### Q31：采集数据明显少了

| 项 | 内容 |
|---|---|
| **现象** | 条数远少于预期 |
| **原因** | ①漏页 ②筛选条件把数据过滤掉了 ③懒加载内容未触发 |
| **解决** | 核对翻页规则；检查筛选条件；对懒加载页面补充"滚动到底部触发加载后再采集" |

### Q32：采集中被网站拦截

| 项 | 内容 |
|---|---|
| **现象** | 出现验证码、访问被拒、账号异常提示 |
| **原因** | 触发网站风控策略 |
| **解决** | ①停止高频访问 ②降低速度、增加间隔 ③分批进行 ④**不要尝试绕过网站明确的安全限制**。必要时联系网站方获取正规数据接口 |

## 八、跨环节通用问题

### Q33：改了配置但要重启吗？

| 工具 | 是否需重启 | 说明 |
|------|-----------|------|
| cc-switch | Claude Code 通常热切换；Codex / Gemini CLI 需重开终端 | 已打开的终端会话不会自动更新 |
| ChatGPT 桌面版 | 改权限后需要重启 | 系统权限变更需重启应用 |
| WorkBuddy 桌面版 | 多数情况无需重启 | 新开会话即可 |
| 浏览器扩展 | 通常即时生效 | 如未生效，重启浏览器 |
| 系统环境变量 | **需要重启终端** | 已打开的终端不会读到新值 |

### Q34：怎么判断到底是哪一环出问题？

| 项 | 内容 |
|---|---|
| **方法** | **逐段验证法**——从最底层往上测 |
| **步骤** | ①`curl` 测中转站本身通不通 → ②看 cc-switch 里供应商是否激活 → ③看配置文件内容对不对 → ④重启终端跑 CLI → ⑤看 CLI 的完整报错 |
| **要点** | 哪一步断了，问题就在那一步。不要跳步猜 |

### Q35：用户想分享配置给同事，怎么做才安全？

| 项 | 内容 |
|---|---|
| **可以分享** | 配置方法、填哪里、步骤说明 |
| **不可分享** | **API Key、账号密码、包含密钥的配置文件截图** |
| **建议** | 让同事从内部正规途径各自获取 Key，各自本地配置 |

## 知识库维护说明

本 FAQ 应随使用持续增补。新增条目时保持以下格式：

```
### Q{编号}：{一句话现象描述}

| 项 | 内容 |
|---|---|
| **现象** | 用户实际看到什么 |
| **原因** | 根本原因（要有技术判断） |
| **解决** | 具体可执行的步骤 |
```

**收录原则**：
- 只收录**真实遇到过**的问题，不编造假设性问题
- 原因必须说得清技术逻辑，不写"可能是网络问题"这种模糊结论
- 解决方案必须**可执行、可验证**
